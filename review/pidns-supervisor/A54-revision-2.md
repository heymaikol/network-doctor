## 4. Arm64 run (slice 1)

Proposed definition, for the maintainer to confirm.

Runs. Native run on linux/arm64 hardware, on a host or a CI runner. Emulated runs (qemu-user, binfmt) and cross-compiled amd64 runs are not accepted, because channel behavior depends on the host kernel ABI. The run is rootless. CGO_ENABLED=0. The toolchain is the go directive in go.mod (go 1.27.3).

Commands, from the repository root:

    CGO_ENABLED=0 go test -count=1 -v -run '^(LIST)$' ./contrib/frr-correlation/supervisor
    CGO_ENABLED=0 go test -count=1 -v -tags integration -run '^(LIST)$' ./contrib/frr-correlation/supervisor

LIST is `TestChannelFramingRows|TestChannelRejectsWrongDescriptorCount|TestChannelDrainCapAndOverflow|TestChanParseOracleSeeds|TestR6IntegerGrammarMatchesRefParse|TestChanDecideIdentityRules|TestChanRecordGrammar|TestChanEscapedRecordGrammar|TestChanRecordStatusFields|FuzzParseWireAgreement|TestRecvOneCallCeiling|TestWalkChanCmsgs`.

TestChannelFramingRows, TestChannelRejectsWrongDescriptorCount and TestChannelDrainCapAndOverflow are in channel_linux_test.go, which has the integration build tag (line 1). They do not compile in the default run, so they are absent from it. That is expected, and it is not a skip.

Counting. Split the job log at its summary lines. The default run is the output above the `default:` line. The integration run is the output between the `default:` and `integration:` lines. The step echoes its own script, and those echoed lines contain the text `--- PASS:`, so a plain grep of the whole log overcounts by two.

Record for each run: the commit tested, uname -m, uname -r, go version, go env GOARCH, and the PASS and FAIL counts per test. For a CI run, record both SHAs that the job prints. The "checked out:" line is the merge ref, and the "pull request head:" line is the PR head. For job 127606284320 (run 42130707996) these are d275dc76 and 6c3d4ee2. The job reports aarch64, kernel 7.0.0-1017-azure, go1.27.3 linux/arm64, and GOARCH arm64.

Merge ref rule. The arm64 job checks out the pull_request merge ref, so the tested tree is the merge commit, not the PR head. A run counts only for its own merge ref, and only when the path set below is unchanged at merge time.

Path set P: contrib/frr-correlation/supervisor, go.mod, go.sum. `go list -deps ./contrib/frr-correlation/supervisor` at 6c3d4ee2 lists no repository package other than the supervisor package itself. There is no go.work and no vendor directory at 6c3d4ee2 or at the merge ref. If a later change makes the package import another repository package, that package's directory joins P before the next run.

At merge time, record the output of these two commands. Exit 0 with no output means the paths are equal.

- M1: `git diff --quiet <merge ref>^2 <PR head> -- P`. The PR side of the merge ref equals the PR head.
- M2: `git diff --quiet <merge ref>^1 origin/main -- P`. Main has not changed P since the merge ref was made.

If M1 or M2 fails, the arm64 run is repeated on the merge ref that will land, and the new record replaces the old one. A change to the supervisor-arm64 job in .github/workflows/ci.yml also needs a new run, because it changes how the evidence is produced. At d275dc76 both commands exit 0 (section 9).

Log checks for a CI run to count: L1, the job conclusion is success. L2, the per-test counts above appear in the run output. L3, the run output has no FAIL line and no panic. The test steps set pipefail (since 124ca047), so a failing go test also fails its step. L3 stays as a second check on the log.
